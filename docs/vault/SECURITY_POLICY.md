# Security Policy & Compliance Vault
# Path: docs/vault/SECURITY_POLICY.md

## 1. Android APK STOMP Messaging Security Checklist
When implementing or maintaining the Android device fleet connectivity (device-gateway via STOMP over WebSockets), the following security checklist MUST be satisfied:

- [ ] **Hardware Keystore Signature**: Every STOMP `CONNECT` frame MUST contain a valid cryptographic signature (`X-Keystore-Sig`) generated by the Android hardware-backed keystore. The backend must verify this signature against the device's registered public key.
- [ ] **Replay Attack Protection**: The payload/headers MUST include a timestamp (`X-Timestamp`) and a cryptographic nonce (`X-Nonce`). 
- [ ] **Nonce Cache**: The backend MUST cache the nonce in Redis (with a TTL equivalent to the allowed timestamp skew) and reject any connection attempt reusing a nonce.
- [ ] **Timestamp Skew**: Connections with a timestamp older than 30 seconds from the server's UTC time MUST be rejected to minimize the replay window.
- [ ] **Payload Deserialization**: Incoming STOMP message payloads must be strictly typed. Do not use polymorphic deserialization (e.g., Jackson `enableDefaultTyping()`) which can lead to Remote Code Execution (RCE) vulnerabilities.

## 2. API Endpoint Compliance Checklist
Before merging any new Controller or REST API endpoint, verify the following:

- [ ] Endpoint uses HTTPS/TLS in production (handled by ingress/proxy).
- [ ] Actuator endpoints (`/actuator/**`) are NOT exposed to the public internet and require internal network access or `SUPER_ADMIN` roles.
- [ ] Endpoint is annotated with `@PreAuthorize("hasRole('...')")` OR the path is explicitly secured in the `SecurityFilterChain`.
- [ ] Sensitive fields (passwords, JWTs, API keys) are never logged in plaintext.
- [ ] Path variables and request parameters are validated to prevent Path Traversal and SQL Injection.
- [ ] Responses do not leak internal database IDs (always use UUIDs).
- [ ] CORS policies are appropriately restricted (avoid `*` origins for authenticated endpoints).

## 3. SMPP Edge Security
- **Failed Binds**: Any `bind_transmitter`, `bind_receiver`, or `bind_transceiver` attempt that fails authentication MUST immediately drop the TCP connection to prevent ghost connections and resource exhaustion.
- **Rate Limiting (TPS)**: SMPP ingress traffic (`submit_sm`) MUST be rate-limited per `system_id` using a distributed counter (e.g., Redis). Exceeding the TPS limit should result in `ESME_RTHROTTLED`.
